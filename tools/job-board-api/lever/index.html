Lever Postings API

Lever publishes every company's job site through the read-only Postings API at api.lever.co, with a separate host for accounts in the European Union. Our index calls it for 1,626 companies a day and holds 56,374 open Lever jobs (18 November 2026).

the endpoint

The Lever job board endpoint

GET https://api.lever.co/v0/postings/{site}?mode=json

  • Authentication: none for reading published postings. Applying through the API needs a key from the company.
  • Format: JSON with mode=json: a list of postings. Without it the API answers with HTML for embedding.
  • Pagination: optional, with skip and limit. Without them one request returns every posting.
ParameterWhat it does
mode=jsonanswer as JSON (other modes return HTML or an iframe)
skip, limitpage through the list
location, commitment, team, department, levelfilter by these categories; repeat a parameter to match any of several values (then case-sensitive)
group=teamgroup postings by location, commitment or team

Other endpoints of the same API:

  • GET /v0/postings/{site}/{posting_id}: one posting
  • https://api.eu.lever.co/v0/postings/{site}: the same API for accounts hosted in the EU

Source: Lever Postings API on GitHub. Checked 19 November 2026.

try it

Request and response

The board of Palantir Technologies, a Lever board from our index, as an example. Replace palantir with the board you need.

curl

curl "https://api.lever.co/v0/postings/palantir?mode=json&limit=10"

Python

import requests

def lever_postings(site):
    # EU accounts live only on api.eu.lever.co; the US host answers 404 for them.
    for host in ("https://api.lever.co", "https://api.eu.lever.co"):
        r = requests.get(f"{host}/v0/postings/{site}", params={"mode": "json"}, timeout=60)
        if r.status_code != 404:
            r.raise_for_status()
            return r.json()
    return []

for p in lever_postings("palantir"):
    print(p["id"], p["text"], p["categories"].get("location"), p["hostedUrl"])

which board

Finding a company's site name

Lever describes the site name as usually the company name with no spaces. It is the first part of the path on the company's Lever job site: jobs.lever.co/palantir means palantir. A job site at jobs.eu.lever.co/<site> belongs to an EU account, and its postings are only on api.eu.lever.co.

Our list of 1,721 companies using Lever shows the careers address of each one, and the address contains the identifier. The list is free to search and download as CSV.

in practice

What we learned reading it every day

  • The full description is in three parts: description (opening), lists (sections such as requirements, each with a title) and additional. Read only the first and you lose the requirements; join all three.
  • EU accounts answer 404 on api.lever.co. Try the EU host when the US one says 404, or start with the EU host for job sites at jobs.eu.lever.co.
  • The company name is not in the response. It is in the title of the job site page, jobs.lever.co/<site>.
  • createdAt is in milliseconds, not seconds.
  • Pay (salaryRange) appears only when the company enters it, mostly for jobs in US states with pay transparency laws.

questions

Frequently asked questions

Does the Lever job board API need an API key?

No. Reading published postings needs no key. The apply endpoint of the Postings API needs a key that the company itself issues.

Is there a rate limit?

Lever documents a limit only for applications (2 per second, then HTTP 429), none for reading postings. One request returns all postings of a site, so a daily read is one call per company. Keep your request rate modest.

Can I get all Lever jobs, from every company, at once?

No. The API answers for one company per request, and Lever publishes no list of its customers. Our index reads 1,626 Lever boards with open jobs every day (56,374 jobs on 18 November 2026); you can search all of them through our Apify actor or get them as a daily job data feed.

Is it allowed to use the Lever job board API?

The API exists so that companies can show their jobs on their own sites and so that job boards can list them. It returns only what the employer has published. Read Lever's documentation and terms for your use, keep request rates modest and link back to the original job for applications.
