Gem Job Board API

Gem publishes each company's job board through a public API at api.gem.com, shaped much like Greenhouse's. Our index calls it for 605 companies a day and holds 4,835 open Gem jobs (25 November 2026).

the endpoint

The Gem job board endpoint

GET https://api.gem.com/job_board/v0/{vanity_url_path}/job_posts/

  • Authentication: none for published job posts.
  • Format: JSON: a list of job posts.
  • Pagination: none; Gem says the API does not use pagination. One request returns every published post.

The feed takes no query parameters.

Other endpoints of the same API:

  • GET /job_board/v0/{vanity_url_path}/job_posts/{id}: one job post; questions=true adds the application questions
  • GET /job_board/v0/{vanity_url_path}/departments/: departments
  • GET /job_board/v0/{vanity_url_path}/offices/: offices

Source: Gem help: the job board API. Checked 19 November 2026.

try it

Request and response

The board of Coupa Software, a Gem board from our index, as an example. Replace coupa-software-inc-ats-1 with the board you need.

curl

curl "https://api.gem.com/job_board/v0/coupa-software-inc-ats-1/job_posts/"

Python

import requests

r = requests.get("https://api.gem.com/job_board/v0/coupa-software-inc-ats-1/job_posts/", timeout=60)
r.raise_for_status()
for p in r.json():
    print(p["id"], p["title"], p["location"]["name"], p.get("location_type"), p["absolute_url"])

which board

Finding a company's job board path

Gem calls it the vanity URL path. It is the first part of the path on jobs.gem.com: jobs.gem.com/coupa-software-inc-ats-1 means coupa-software-inc-ats-1. Some IDs are a readable company name, others a generated one like this.

Our list of 609 companies using Gem shows the careers address of each one, and the address contains the identifier. The list is free to search and download as CSV.

in practice

What we learned reading it every day

  • The company name is not a field. Use the board's page title, or the company named in the description.
  • location_type is the clean remote signal; offices tell you where an on-site or hybrid job is.
  • Posts stay published for a long time on some boards (the example above was first published in 2025). Use updated_at and your own first-seen date to judge freshness.
  • Gem answers HTTP 429 when read too fast. Read each board once a day and back off when asked.

questions

Frequently asked questions

Does the Gem job board API need an API key?

No. The job board API returns published job posts without a key; only submitting applications through it needs one.

Is there a rate limit?

Gem documents 20 requests per second with bursts of 500 per API key, and does not say what applies to reads without a key. It does answer fast readers with HTTP 429. One request returns all job posts of a board, so a daily read is one call per company.

Can I get all Gem jobs, from every company, at once?

No. The API answers for one company per request, and Gem publishes no list of its customers. Our index reads 605 Gem boards with open jobs every day (4,835 jobs on 25 November 2026); you can search all of them through our Apify actor or get them as a daily job data feed.

Is it allowed to use the Gem job board API?

The API exists so that companies can show their jobs on their own sites and so that job boards can list them. It returns only what the employer has published. Read Gem's documentation and terms for your use, keep request rates modest and link back to the original job for applications.
